# בקרת מנופים — מערכת שליטה ובקרה על הפעלת צמ"ה

אפליקציית ווב (SPA) קלה: HTML + Tailwind CDN + JavaScript ES Modules, מחוברת ישירות ל-Firebase Authentication ו-Cloud Firestore. אין צורך ב-Node.js או ב-Build. האפליקציה מתארחת ב-**GitHub Pages**.

**כתובת:** https://itairosenblum-hash.github.io/crane-control/

## מבנה הקבצים
| קובץ | תפקיד |
|---|---|
| `index.html` | Markup, Tailwind CDN, עיצוב רכיבים |
| `js/config.js` | הגדרות Firebase, ערכי ברירת מחדל לספי התראה, חלון 72 שעות |
| `js/auth.js` | אתחול Firebase והתחברות עם Google |
| `js/firestore.js` | כל הגישה לנתונים, כולל טרנזקציות פתיחה וסגירה של הפעלה |
| `js/ui.js` | המסכים: מפעיל, מנהל אתר, מנהל מערך, וניתוב לפי תפקיד |
| `firestore.rules` | חוקי אבטחה |
| `sw.js` | Service worker מינימלי, מאפשר התראות מערכת בטלפון |

## הקמה (פעם אחת)
1. **Firebase Console → פרויקט `crane`:**
   - Build → **Authentication** → Get started → Sign-in method → להפעיל **Google**.
   - Build → **Firestore Database** → Create database (Production mode, אזור `eur3` או `me-west1`).
   - Project settings → General → Your apps → Web app: להעתיק את `apiKey` לקובץ `js/config.js` (שאר הערכים כבר מוגדרים).
2. **חוקי אבטחה:** Firestore → Rules → להדביק את התוכן של `firestore.rules` → Publish.
3. **דומיין מורשה:** Authentication → Settings → Authorized domains → להוסיף את `itairosenblum-hash.github.io`.
4. **פריסה:** GitHub → Settings → Pages → Deploy from a branch → `main` / `(root)`. כל push ל-`main` מתפרסם אוטומטית תוך דקה-שתיים.
5. **מנהל המערך הראשון:** להתחבר לאתר ולשלוח בקשת הרשאה. אחר כך ב-Firestore → `users` → המסמך שלך, לשנות ידנית את `role` ל-`admin` ואת `status` ל-`approved`. המסך יתעדכן מיד. מכאן והלאה כל האישורים נעשים מתוך המערכת.

## זרימת עבודה
- **משתמש חדש:** מתחבר עם Google, ממלא שם, טלפון ותפקיד מבוקש, וממתין לאישור. המסך מתעדכן אוטומטית כשהבקשה מאושרת.
- **מפעיל:** בוחר מנוף פנוי באתר שלו וממלא בדיקת פתיחה. ההפעלה נפתחת והשעון רץ. בסיום ממלא בדיקת סגירה, חותם, והמנוף חוזר לסטטוס פנוי.
- **מנהל אתר:** רואה התרעות קריטיות, מנופים בהפעלה בזמן אמת, מצב צי המנופים ויומן של 72 השעות האחרונות. יכול לבצע סגירה כפויה להפעלה שנשכחה פתוחה. מנהל אתר בלי שיוך לאתר רואה את כל האתרים.
- **מנהל מערך:** אישור או דחייה של בקשות (כולל שיוך תפקיד ואתר), ניהול משתמשים ומנופים, תמונת מצב עם סינון לפי אתר, והיסטוריה עם סינון וייצוא ל-Excel.

## התראות
מנהל המערך קובע הכל בלשונית **🔔 הגדרות התראות**:
- **מדדי התראה (לכל המערכת, נשמר ב-`settings/alerts`):**
  - דלק ואוראה: סף להתראה ראשונית וסף להתראה חמורה. אפשר גם לכבות מדד.
  - שמן, מים, רצועות, שקלים, חתולים: מה קורה כשהפריט מסומן "לא תקין". האפשרויות הן ללא התראה, התראה ראשונית או התראה חמורה.
  - ברירות המחדל: דלק 30%/15%, אוראה 25%/10%. שמן ומים מוגדרים כחמורים, ציוד ההרמה כהתראה ראשונית.
- **ההתראות שלי (אישי, נשמר ב-`users/{uid}.notifyPrefs`):** האם לקבל התראות, האם רק חמורות או גם ראשוניות, התראת מערכת בטלפון/מחשב, וצליל.
- התראה נשלחת כשנפתחת הפעלה חדשה עם ליקוי. היא מגיעה כל עוד המערכת פתוחה בדפדפן, גם כשהלשונית ברקע. כדי לקבל התראות גם כשהאפליקציה סגורה לגמרי, צריך Firebase Cloud Messaging עם Cloud Functions (תוכנית Blaze).
- חומרת הליקויים מחושבת לפי ההגדרות הנוכחיות, כך ששינוי מדד משפיע גם על התצוגה של הפעלות קודמות.

## הערות טכניות
- פתיחה וסגירה של הפעלה מתבצעות **בטרנזקציה**, כך ששני מפעילים לא יכולים לתפוס את אותו מנוף.
- כל השאילתות עובדות עם האינדקסים האוטומטיים של Firestore, בלי צורך ליצור אינדקסים מורכבים.
- מטמון מקומי (persistent cache) מאפשר טעינה מהירה גם בקליטה חלשה. פתיחה וסגירה של הפעלה דורשות חיבור לרשת.
