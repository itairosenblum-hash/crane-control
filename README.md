# בקרת מנופים — מערכת שליטה ובקרה על הפעלת צמ"ה

אפליקציית ווב (SPA) קלה: HTML + Tailwind CDN + JavaScript ES Modules, מחוברת ישירות ל-Firebase Authentication ו-Cloud Firestore. אין צורך ב-Node.js או ב-Build. האפליקציה מתארחת ב-**GitHub Pages**.

**כתובת:** https://itairosenblum-hash.github.io/crane-control/

## מבנה הקבצים
| קובץ | תפקיד |
|---|---|
| `index.html` | Markup, Tailwind CDN, עיצוב רכיבים |
| `js/config.js` | הגדרות Firebase, ערכי ברירת מחדל לספי התראה, חלון 72 שעות |
| `js/auth.js` | אתחול Firebase והתחברות עם Google |
| `js/firestore.js` | כל הגישה לנתונים, כולל טרנזקציות פתיחה וסגירה של הפעלה |
| `js/ui.js` | המסכים: מפעיל, מנהל אתר, מנהל מערך, וניתוב לפי תפקיד |
| `firestore.rules` | חוקי אבטחה |
| `sw.js` | Service worker מינימלי, מאפשר התראות מערכת בטלפון |

## חיבור למערכת הציוד הקיימת
המערכת רצה על פרויקט ה-Firebase `cranes` (`cranes-a0759`), לצד מערכת הציוד הקיימת.
- **אוספים של המערכת הזו:** `craneUsers`, `craneSettings`, `cranes`, `operations`.
- **מהמערכת הקיימת המערכת רק קוראת, ולא כותבת:**
  - `equipment`: תוקף התסקיר הוא המוקדם מבין `nextCheck` ו-`btNext`. הצ' נלקח מ-`serialNumber`.
  - `operators`: תאריכי רישיון: `craneLicenseExpiry`, `militaryLicenseExpiry`, `civilianLicenseExpiry`, `tatash`.
  - `sites`: רשימת האתרים.
- **האוספים `users` ו-`meta`** שייכים למערכת הקיימת, והמערכת הזו לא נוגעת בהם.

## הקמה (פעם אחת)
1. **Firebase Console → פרויקט `cranes`:**
   - Authentication → Sign-in method → להפעיל **Google**. ספק ההתחברות הקיים של המערכת הישנה נשאר כמו שהוא.
   - Authentication → Settings → Authorized domains → להוסיף `itairosenblum-hash.github.io`.
2. **חוקי אבטחה:** Firestore → Rules → להחליף את כל התוכן ב-`firestore.rules` → Publish.
   - הקובץ כולל את החוקים של המערכת הקיימת. הכתיבה לאוספים `users`, `sites`, `equipment`, `operators` ו-`meta` לא השתנתה.
   - **שינוי אחד:** קריאה מ-`sites`, `equipment` ו-`operators` מותרת רק למשתמש שיש לו מסמך ב-`users` (המערכת הקיימת), או למשתמש מאושר במערכת המנופים. קודם הייתה מותרת לכל משתמש מחובר. מפעיל במערכת המנופים רואה רק את רשומת המנופאי שלו.
3. **פריסה:** GitHub → Settings → Pages → Deploy from a branch → `main` / `(root)`.
4. **חשבונות קבועים** (מוגדרים ב-`js/config.js` וב-`isFixedAdmin()` שבקובץ `firestore.rules`):
   - `itai.rosenblum@gmail.com`: **מפתח**. הרשאות מלאות, לא מקבל התראות.
   - `filiba111@gmail.com`: **מנהל מערך**. הרשאות מלאות, מקבל התראות לפי ההגדרות שלו.
   - מספיק להתחבר עם Google, והחשבון מוגדר כמנהל אוטומטית. לא צריך לערוך שום דבר ידנית ב-Firestore.
5. **קישורים** (מתוך המערכת):
   - **מנופים** ← לבחור לכל מנוף את רשומת הציוד שלו. מזהה המנוף ימולא אוטומטית מהצ'.
   - **משתמשים** ← באישור מפעיל, המערכת מציעה את רשומת המנופאי לפי ת"ז.

## התראות לטלפון (Push), גם כשהאתר סגור
- **רכיבים:**
  - בצד האתר: `js/push.js`, `sw.js` ו-`manifest.webmanifest`.
  - בצד השרת: Cloud Functions בתיקייה `functions/`, באזור `me-west1`.
- **הפונקציות:**
  - `notifyOnOperation`: נפתחה הפעלה עם ליקוי? נשלחת התראה מיידית למנהלי המערך, ולמנהל האתר הרלוונטי, לפי ההעדפות של כל אחד.
  - `dailyExpiryDigest`: כל בוקר בשעה 07:00 נשלח סיכום של תסקירים ורישיונות שפגו או עומדים לפוג. הסיכום נשלח רק אם יש כאלה.
  - `sendTestPush`: הכפתור "שלח בדיקה לטלפון" בהגדרות.
- **חשבון המפתח** (`itai.rosenblum@gmail.com`) לא מקבל התראות.
- **הפעלה במכשיר:** לשונית 🔔 הגדרות התראות ← "התראות לטלפון" ← שמור. ההפעלה נעשית בנפרד בכל מכשיר.
  - **באייפון:** קודם פותחים את האתר ב-Safari ← שיתוף ← "הוסף למסך הבית". אחר כך פותחים את האתר מהאייקון ומפעילים התראות.
  - **באנדרואיד:** אפשר ישירות מ-Chrome. מומלץ להתקין דרך התפריט ⋮ ← "התקנת אפליקציה".
- **זהות האפליקציה המותקנת** היא `/crane-control/`, נפרדת מכל אפליקציה אחרת באותו דומיין.

### התקנת הפונקציות בשרת (פעם אחת, ושוב רק כשמשנים את `functions/`)
1. פותחים את [Google Cloud Shell](https://shell.cloud.google.com/?show=terminal), מחוברים עם החשבון שהוא בעלים של הפרויקט.
2. מדביקים ומריצים:
   ```bash
   rm -rf crane-control && git clone https://github.com/itairosenblum-hash/crane-control && cd crane-control/functions && npm install && cd .. && npx -y firebase-tools@latest deploy --only functions:crane-control --project cranes-a0759
   ```
3. אם מופיעה בקשת התחברות, מריצים `npx -y firebase-tools@latest login --no-localhost`, מאשרים בקישור שמופיע, ואז מריצים שוב את הפקודה מסעיף 2.

> ⚠️ **לא להשתמש ב-`--force` ולא ב-`--only functions` בלי `:crane-control`.** הפונקציות של מערכת הציוד הקיימת (`scanCertificate`, מהריפו `crane`) נמצאות באותו פרויקט, בקבוצת הפונקציות `default`. פקודה רחבה מדי עלולה למחוק אותן, וגם הפריסה של מערכת הציוד עלולה למחוק את הפונקציות של המערכת הזו. בגלל זה הפונקציות של המערכת הזו מוגדרות בקבוצה נפרדת, `crane-control`, ומתקינים רק אותה.

בהתקנה הראשונה Firebase מפעיל אוטומטית את השירותים הנדרשים (Cloud Functions, Cloud Build, Eventarc, Cloud Scheduler). זה יכול לקחת כמה דקות.
העלות בפועל בהיקף כזה היא בערך ₪0, כי הכל בתוך המכסה החינמית של Blaze.

- **מפעיל:** בוחר מנוף פנוי באתר שלו וממלא בדיקת פתיחה. ההפעלה נפתחת והשעון רץ. בסיום ממלא בדיקת סגירה, חותם, והמנוף חוזר לסטטוס פנוי.
- **מנהל אתר:** רואה התראות קריטיות, מנופים בהפעלה בזמן אמת, מצב צי המנופים ויומן של 72 השעות האחרונות. יכול לבצע סגירה כפויה להפעלה שנשכחה פתוחה. מנהל אתר בלי שיוך לאתר רואה את כל האתרים.
- **מנהל מערך:**
  - אישור או דחייה של בקשות, כולל שיוך תפקיד, אתר ורשומת מנופאי.
  - ניהול משתמשים ומנופים, כולל קישור מנוף לרשומת הציוד שלו.
  - תמונת מצב: מסוננת לפי אתר, עם ריכוז של תסקירים ורישיונות שפגו או עומדים לפוג.
  - היסטוריה עם סינון וייצוא ל-Excel.
  - הגדרות התראות.

## התראות
מנהל המערך קובע הכל בלשונית **🔔 הגדרות התראות**:
- **מדדי התראה (לכל המערכת, נשמר ב-`settings/alerts`):**
  - דלק ואוראה: סף להתראה ראשונית וסף להתראה חמורה. אפשר גם לכבות מדד.
  - שמן, מים, רצועות, שקלים, חתולים: מה קורה כשהפריט מסומן "לא תקין". האפשרויות הן ללא התראה, התראה ראשונית או התראה חמורה.
  - ברירות המחדל: דלק 30%/15%, אוראה 25%/10%. שמן ומים מוגדרים כחמורים, ציוד ההרמה כהתראה ראשונית.
- **תוקף תסקיר ורישיון:**
  - נבדק בכל פתיחת הפעלה, ישירות מול `equipment` ו-`operators`.
  - לכל אחד מהם קובעים: האם תוקף שפג הוא התראה ראשונית או חמורה, האם הוא חוסם פתיחת הפעלה, וכמה ימים מראש תגיע התראה מוקדמת.
  - ברירות המחדל: התראה חמורה, חוסם, 30 יום מראש. נבדק רק רישיון מנוף נייד.
- **ההתראות שלי (אישי, נשמר ב-`users/{uid}.notifyPrefs`):** האם לקבל התראות, האם רק חמורות או גם ראשוניות, התראת מערכת בטלפון/מחשב, וצליל.
- התראה נשלחת כשנפתחת הפעלה חדשה עם ליקוי. היא מגיעה כל עוד המערכת פתוחה בדפדפן, גם כשהלשונית ברקע. כדי לקבל התראות גם כשהאפליקציה סגורה לגמרי, צריך Firebase Cloud Messaging עם Cloud Functions (תוכנית Blaze).
- חומרת הליקויים מחושבת לפי ההגדרות הנוכחיות, כך ששינוי מדד משפיע גם על התצוגה של הפעלות קודמות.

## הערות טכניות
- פתיחה וסגירה של הפעלה מתבצעות **בטרנזקציה**, כך ששני מפעילים לא יכולים לתפוס את אותו מנוף.
- כל השאילתות עובדות עם האינדקסים האוטומטיים של Firestore, בלי צורך ליצור אינדקסים מורכבים.
- מטמון מקומי (persistent cache) מאפשר טעינה מהירה גם בקליטה חלשה. פתיחה וסגירה של הפעלה דורשות חיבור לרשת.
